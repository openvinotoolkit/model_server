# RC4 Windows release plan

**Goal:** Publish the selected 2026.4 parser-retainer source and custom GPU runtime as genuine Python On and Python Off OVMS Windows packages, then establish the identical source tree on fork main.

**Architecture:** Use the existing isolated 2026.4 checkout and pinned SDK. Preserve the measured Python Off artifact before changing Bazel configuration. Follow windows_build.bat and windows_create_package.bat conventions with explicit local paths, immutable staging and per-file hashes. Python On includes its compiled backend, pyovms binding and embedded CPython 3.12.10; Python Off includes none of these Python payloads.

**Tech stack:** Bazel, MSVC 14.44.35207, OpenVINO/GenAI 2026.4 RC1 SDK, custom GPU plugin 21a2fd9f, CPython 3.12.10.

## Constraints

- Do not edit Gemma4 parser files or reopen its parser acceptance.
- Do not import upstream/main, C6/2026.5, OTD or CIB2 product changes.
- Preserve existing main history, unrelated worktrees and uncommitted changes.
- Publish unsigned fork prerelease packages with exact provenance; no implied Intel signing or full release qualification.
- Serialize builds and GPU tests. Never overwrite the installed C:\llm\ovms deployment.
